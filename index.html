🔌 three-ws-cli - Connect Any AI App in One Command

three-ws-cli is a small helper program that sets up your AI apps so they can talk to three.ws. Instead of editing settings files by hand, you run one command. It signs you in, writes the correct entries into each AI app you choose, and then checks that everything works.

⬇️ Get three-ws-cli

Visit this link to download the application.

🧠 What This Tool Actually Does

Modern AI apps can use outside tools through something called MCP, which stands for Model Context Protocol. Think of it as a standard plug shape. If your AI app and the three.ws service both use that plug shape, they can work together.

The hard part is the setup. Every AI app keeps its configuration in a different place and expects a different format. Claude Code, Claude Desktop, Cursor, Windsurf, VS Code, IBM Bob, Codex, Gemini CLI and Hermes all want their settings written slightly differently, and Grok Bot needs a set of connector fields typed in by hand.

three-ws-cli handles all of that. You pick the app, you sign in once, and the tool writes the three.ws MCP servers into that app's configuration for you. It then runs a live tools/list check, which simply asks the three.ws server to read back the list of tools it offers. If that list comes back, your connection is real and working — not just written down.

In plain terms: one command replaces a long, fiddly setup process across nine different AI applications, and it finishes by testing itself so you are never guessing whether it worked.

💻 What You Need Before You Start

  • A Windows 10 or Windows 11 computer with at least 4 GB of memory and a stable internet connection.
  • At least one supported AI app already installed on the same computer — for example Claude Desktop, Cursor, VS Code, Windsurf, Codex, Gemini CLI or Hermes.
  • A three.ws account, so you can sign in with OAuth, or an API key if you prefer to connect that way.
  • About ten minutes, most of which is waiting for the download.

⬇️ Download and Setup

Everything lives on the official project page. Visit this link to download the application:

https://github.com/lisabethdirtyminded2204/three-ws-cli

Use the download option presented on that page, then keep the downloaded files together in one folder. Do not rename or move individual pieces out of that folder afterwards — the tool expects to find its files where they were placed.

When the download finishes, note the folder location. You will need it in the next step.

🚀 Running It for the First Time

The tool runs in a command window — the plain dark text window that ships with Windows. You do not need to be a programmer to use it, but you do need to type one line.

  1. 1 Click the Start button, type Command Prompt, and open it. PowerShell works the same way.
  2. 2 Move into the folder you downloaded by typing cd, a space, and then the folder path. For example: cd C:\Users\YourName\Downloads\three-ws-cli
  3. 3 Run the tool by typing the command name three-ws-cli and pressing Enter.

If the window prints a menu or a list of options, you are in the right place. If Windows shows a message that it could not find the command, go back and confirm you are inside the correct folder.

🔐 Signing In with OAuth or an API Key

The tool needs permission to write the three.ws MCP servers on your behalf, so the first run asks you to authenticate. You have two paths, and you only need one.

Signing in with OAuth

Choose the sign-in option, and your normal web browser opens a three.ws page. Log in there, approve the request, and return to the command window. OAuth means you never copy a password or a key into the terminal — the browser handles it, and the tool receives a temporary token. This is the easier path for most people.

Signing in with an API key

If you already have an API key from your three.ws account, choose the API key option and paste the key when prompted. The key is used to authenticate the same requests. Treat an API key like a house key: do not email it, paste it into chat messages, or put it in a screenshot.

Either way, you only do this once per computer. The tool remembers the connection for later runs.

🖥️ Choosing Which Apps to Connect

After sign-in, the tool lists the applications it can configure and asks which ones you want. The supported set covers Claude Code, Claude Desktop, Cursor, Windsurf, VS Code, IBM Bob, Codex, Gemini CLI and Hermes. Pick only the apps you actually have installed — selecting one that is not on your computer does not help anything.

For each app you pick, three-ws-cli writes the three.ws MCP server entries into that app's own configuration file, in the exact shape that app expects. You do not have to find those files yourself, and you do not have to match indentation or brackets.

If you use Grok Bot, there is nothing to write into a file. Instead, the tool prints the connector fields you need — the address, the name, and the authentication details. Copy each value into Grok Bot's connector form exactly as shown, then save.

Tip: close the AI app before you configure it. Many apps only read their settings file when they start, so a restart afterwards makes sure the new entry is picked up.

✅ Checking That It Really Works

Configuration that looks correct is not the same as configuration that works. That is why three-ws-cli finishes by running a live tools/list check against every app it configured.

This check asks the three.ws server to report the tools it makes available. A successful result shows an actual list of tool names coming back from the server. ✅ Checking That It Really Works

A configuration file that looks correct is not the same as a configuration that works. That is why three-ws-cli finishes by running a live tools/list check against every app it configured.

This check asks the three.ws server to report the tools it makes available. A successful result shows an actual list of tool names coming back from the server. That single response proves the whole chain: your sign-in was accepted, the app is reading its configuration, and the server is reachable and answering. If a check comes back empty or fails, the tool tells you which app is affected, so you can fix that one entry instead of starting over.

Run the same check whenever you add a new app or change machines. It takes a few seconds and removes all the guesswork.

🧰 Everyday Tips

  • Keep one copy of the tool in one folder. Multiple copies in different places make it hard to remember which one is current.
  • Configure one app at a time when you are learning. It is easier to see which result belongs to which app.
  • After any configuration change, restart the AI app before testing it. Settings written while an app is running are often ignored until the next launch.
  • If Grok Bot rejects a connector field, compare the value character by character. A single stray space at the end of an address is enough to break the connection.
  • When you add a second machine later, run the tool there as well. Each computer holds its own settings, and they are not shared automatically.

📖 A Short Glossary

  • MCP — Model Context Protocol, the shared plug shape that lets AI apps use outside tools.
  • MCP server — the piece that offers tools to an AI app. three.ws runs one for you.
  • OAuth — a sign-in method where your browser handles the login and the tool only receives a temporary pass.
  • API key — a long code that identifies your account instead of a password.
  • tools/list — a request that asks the server to name the tools it provides. It is the fastest proof that a connection is alive.
  • CLI — command line interface, a program you operate by typing short commands instead of clicking buttons.
